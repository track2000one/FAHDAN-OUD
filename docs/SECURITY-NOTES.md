# ملاحظات الأمان قبل الإنتاج

1. جميع الأسعار والأرصدة المعروضة في واجهة React ليست مصدرًا موثوقًا للشراء؛ يجب احتساب الطلب والتحقق من الرصيد في API ضمن معاملة قاعدة بيانات واحدة.
2. واجهة المنتجات العامة تُرجع حقول العرض فقط، ولا تُرجع المورد أو التكلفة أو حركات المخزون. لوحة الإدارة تتطلب توكنًا صالحًا ودور مالك/مدير.
3. JWT في sessionStorage حل مرحلة تأسيسية؛ يفضل عند الإنتاج استخدام Cookies آمنة HttpOnly مع CSRF protection وإبطال الجلسات وتدوير المفاتيح وMFA لحساب المالك.
4. لا تُضمّن أبدًا DATABASE_URL أو مفاتيح الدفع أو ADMIN_PASSWORD في الواجهة أو GitHub. ملف .env مستثنى من git.
5. `prisma db push` مناسب لتطوير هذا النموذج، وليس آلية ترحيل إنتاجية. أنشئ migrations مُراجعة قبل أول نشر.
6. `SEED_DEMO=true` للتطوير المحلي فقط. المنتجات التجريبية مخفية عبر API عند `NODE_ENV=production`.
7. قبل تفعيل الدفع يلزم المصادقة على Webhooks، ومفاتيح Idempotency، وحجز الأرصدة وانتهاء صلاحيتها، وحماية PII وفواتير العملاء.
8. لا توجد سياسة شحن أو إرجاع أو سياسة ضرائب معتمدة بعد، فلا تعرض عبارات تأكيد غير صحيحة للعملاء.
9. لابد من إعادة الحساب والتحقق من فواتير المورد والتكلفة الموزعة وحركات المخزون قبل عرض الربح على أنه نهائي.
10. `robots.txt` ووسم noindex يمنعان الفهرسة أثناء التطوير ويجب مراجعتهما عند الإطلاق.
